# Бизнес-требования

> Документ описывает бизнес-требования к платформе для детей и родителей (развивающие игры + ИИ-помощник на основе методологии позитивного родительства). Требования сгруппированы по иерархии: **Раздел → Эпик → Стори**.

---

## Общие сведения о проекте

### Название проекта

Платформа для детей и родителей, объединяющая развивающие игры и интеллектуального помощника с опорой на методологию позитивного родительства (рабочее название уточняется).

### Суть проекта

Веб-сервис, который в одной экосистеме поддерживает и ребёнка, и родителя.

- **Для детей:** увлекательные игры, направленные на развитие софт-навыков (эмоциональный интеллект, коммуникация, саморегуляция), а также дружелюбный ИИ-помощник, который поддерживает ребёнка в моменты грусти и стресса.
- **Для родителей:** чат-помощник, отвечающий на вопросы о воспитании в рамках заданной методологии, и личный дашборд с информацией о занятиях, успехах и эмоциональном состоянии ребёнка.

### Целевая аудитория

- **Родители** детей старшего дошкольного и младшего школьного возраста, родители подростков, заинтересованные в осознанном воспитании и развитии эмоциональных навыков ребёнка.
- **Дети** — самостоятельные пользователи с адаптированным интерфейсом.

### Ключевой функционал

#### Для детей
- Каталог развивающих игр на софт-навыки с фиксацией прогресса.
- ИИ-помощник, поддерживающий ребёнка в трудных эмоциональных ситуациях (с ограниченным, безопасным сценарием общения).

#### Для родителей
- Чат-помощник на основе методологии: отвечает на вопросы о воспитании доброжелательным тоном, помогает в сложных ситуациях (например, после ссоры с ребёнком).
- Дашборд по каждому ребёнку: активность в играх, динамика навыков, эмоциональные маркеры.

### Общая модель работы

1. Родитель регистрируется и заводит профиль ребёнка.
2. Ребёнок подключается к аккаунту по коду/ссылке без собственной электронной почты.
3. ИИ-ассистент для родителей строится на базе большой языковой модели с набором знаний (RAG или файн-тюнинг) по загруженной методологии; ответы проходят модерацию.

### Особенности и ограничения

- **Данные детей — чувствительная категория:** минимизация собираемых данных, модерация детского чата, продуманная политика хранения и удаления переписки.
- **ИИ-помощник не заменяет психолога:** при темах, связанных с риском, предусмотрено мягкое перенаправление к специалисту.

## Условные обозначения

- **Раздел** — крупный функциональный блок (ID: `Раздел N`).
- **Эпик** — группа связанных пользовательских историй внутри раздела (ID: `Эпик N.M`).
- **Стори (User Story)** — отдельное пользовательское требование (ID: `US-N.M.K`), описывается по шаблону «Как… я хочу… чтобы…» с критериями приёмки.

### Приоритеты User Story

| Приоритет | Значение |
|-----------|----------|
| **P0** | Критический — без этого продукт не может работать вообще (core-путь, обязательный для первого релиза) |
| **P1** | Высокий — должно быть в первом релизе, без этого продукт работает неполноценно |
| **P2** | Средний — важно, но можно отложить на второй релиз |
| **P3** | Низкий — nice-to-have, реализуется когда будут ресурсы |

## Раздел 1. Авторизация

**Описание:** раздел охватывает регистрацию, вход и восстановление доступа для родителя (основной пользователь с собственной электронной почтой), а также подключение ребёнка к аккаунту родителя по коду/ссылке без собственной почты.

**Роли:**
- **Родитель** — владелец аккаунта, регистрируется по email.
- **Ребёнок** — подключается к аккаунту родителя, не имеет собственного email.

---

### Эпик 1.1 Вход по email

**Описание:** эпик описывает процесс входа родителя в сервис по электронной почте и паролю, включая ввод и валидацию данных, обработку ошибок и успешную авторизацию.

**Предусловия:** у родителя есть подтверждённый аккаунт, зарегистрированный по email.

---

#### US-1.1.1. Ввод email для входа

**Приоритет: P0**

**Как** родитель,
**я хочу** ввести свой email на экране входа,
**чтобы** начать авторизацию в сервисе.

**Критерии приёмки:**
1. На экране входа отображается поле для ввода email.
2. Поле проверяет корректность формата email (наличие `@` и домена) до отправки формы.
3. При некорректном формате отображается понятное сообщение об ошибке, кнопка продолжения заблокирована.
4. Введённое значение сохраняется при переходе к вводу пароля (не очищается).
5. Ввод email нечувствителен к регистру (`User@mail.ru` = `user@mail.ru`).

**Риски:**
- R1.1.1-1: Пользователь может ввести несуществующий email — ** mitigation:** валидация формата на клиенте и сервере.
- R1.1.1-2: Боты могут автоматизировать ввод — **mitigation:** капча при подозрительной активности.

---

#### US-1.1.2. Ввод пароля для входа

**Приоритет: P0**

**Как** родитель,
**я хочу** ввести пароль после email,
**чтобы** подтвердить, что я владелец аккаунта.

**Критерии приёмки:**
1. На экране отображается поле для ввода пароля со скрытыми символами.
2. Доступна возможность показать/скрыть введённый пароль.
3. Кнопка «Войти» активна только при заполненных полях email и пароля.
4. Пароль не отображается в открытом виде в логах и сетевых запросах (передаётся по защищённому каналу).

**Риски:**
- R1.1.2-1: Пароль может быть перехвачен — **mitigation:** HTTPS, хеширование на сервере.
- R1.1.2-2: Пользователь может забыть пароль — **mitigation:** ссылка «Забыли пароль?».

---

#### US-1.1.3. Успешный вход в аккаунт

**Приоритет: P0**

**Как** родитель,
**я хочу** войти в сервис после ввода корректных email и пароля,
**чтобы** получить доступ к своему личному кабинету.

**Критерии приёмки:**
1. При корректной паре email + пароль пользователь авторизуется и перенаправляется на главный экран (дашборд родителя).
2. Сессия пользователя сохраняется в соответствии с политикой хранения сессий.
3. Время отклика при успешном входе соответствует заданным требованиям к производительности.

**Риски:**
- R1.1.3-1: Сервер может быть недоступен — **mitigation:** мониторинг, алерты, резервные серверы.
- R1.1.3-2: Сессия может быть скомпрометирована — **mitigation:** secure cookies, HTTP-only, CSRF защита.

---

#### US-1.1.4. Обработка ошибки неверных данных

**Приоритет: P1**

**Как** родитель,
**я хочу** получать понятное сообщение при неверном email или пароле,
**чтобы** понимать причину отказа и повторить попытку.

**Критерии приёмки:
1. При неверной паре email + пароль отображается сообщение об ошибке без указания, какое именно поле неверно (из соображений безопасности).
2. Введённый email сохраняется, поле пароля очищается.
3. Реализована защита от перебора: после заданного числа неудачных попыток вход временно блокируется / применяется дополнительная проверка.

**Риски:**
- R1.1.4-1: Легитимный пользователь может быть заблокирован — **mitigation:** разблокировка по email.
- R1.1.4-2: Сообщение об ошибке может раскрыть информацию — **mitigation:** универсальное сообщение.

---

#### US-1.1.5. Переход к восстановлению пароля

**Приоритет: P1**

**Как** родитель,
**я хочу** перейти к восстановлению пароля с экрана входа,
**чтобы** вернуть доступ, если забыл пароль.

**Критерии приёмки:**
1. На экране входа есть ссылка/кнопка «Забыли пароль?».
2. По нажатию пользователь переходит к сценарию восстановления доступа.
3. Если email уже был введён, он подставляется в сценарий восстановления.

**Риски:**
- R1.1.5-1: Ссылка восстановления может быть перехвачена — **mitigation:** одноразовые токены, короткий срок действия.
- R1.1.5-2: Ссылка может быть передана третьему лицу — **mitigation:** привязка к IP/сессии.

### Эпик 1.2 Регистрация родителя

**Описание:** эпик описывает процесс создания аккаунта родителя с вводом email, созданием пароля и подтверждением данных.

**Предусловия:** у пользователя нет аккаунта в системе.

---

#### US-1.2.1. Ввод email для регистрации

**Приоритет: P0**

**Как** новый пользователь,
**я хочу** ввести email для регистрации,
**чтобы** создать аккаунт родителя.

**Критерии приёмки:
1. На экране регистрации отображается поле для ввода email.
2. Система проверяет формат email перед отправкой формы.
3. Система проверяет, что email не зарегистрирован ранее, до завершения регистрации.
4. При использовании уже зарегистрированного email отображается сообщение с предложением войти или восстановить пароль.

**Риски:**
- R1.2.1-1: Email может быть чужим — **mitigation:** подтверждение email перед завершением регистрации.
- R1.2.1-2: Массовая регистрация ботами — **mitigation:** капча, rate limiting.

---

#### US-1.2.2. Создание пароля

**Приоритет: P0**

**Как** новый пользователь,
**я хочу** создать пароль при регистрации,
**чтобы** обеспечить безопасность своего аккаунта.

**Критерии приёмки:
1. Поле ввода пароля со скрытыми символами и возможностью показать/скрыть.
2. Система требует пароль минимальной длины (не менее 8 символов).
3. Отображается индикатор сложности пароля (слабый / средний / сильный).
4. Пароль передаётся по защищённому каналу и не хранится в открытом виде.

**Риски:**
- R1.2.2-1: Слабый пароль — **mitigation:** индикатор сложности, минимальные требования.
- R1.2.2-2: Пользователь может использовать тот же пароль на других ресурсах — **mitigation:** рекомендация уникальных паролей.

---

#### US-1.2.3. Подтверждение email

**Приоритет: P0**

**Как** новый пользователь,
**я хочу** подтвердить свой email,
**чтобы** завершить регистрацию и получить доступ к аккаунту.

**Критерии приёмки:
1. После ввода данных пользователь получает письмо со ссылкой подтверждения на указанный email.
2. По переходу по ссылке email помечается как подтверждённый и пользователь автоматически авторизуется.
3. Ссылка подтверждения имеет ограниченный срок действия (например, 24 часа).
4. При повторной отправке письма генерируется новая ссылка.

**Риски:**
- R1.2.3-1: Письмо может не дойти — **mitigation:** повторная отправка, проверка спам-фильтров.
- R1.2.3-2: Ссылка может быть использована третьим лицом — **mitigation:** короткий срок действия, одноразовый токен.

---

#### US-1.2.4. Принятие пользовательского соглашения и политики конфиденциальности

**Приоритет: P0**

**Как** новый пользователь,
**я хочу** принять пользовательское соглашение и политику конфиденциальности при регистрации,
**чтобы** подтвердить согласие на обработку данных.

**Критерии приёмки:
1. На экране регистрации отображается чекбокс с ссылкой на пользовательское соглашение и политику конфиденциальности.
2. Регистрация невозможна без отметки чекбокса.
3. Ссылки открывают документы в новой вкладке для ознакомления.
4. Факт принятия соглашения фиксируется в системе.

**Риски:**
- R1.2.4-1: Пользователь может не прочитать соглашение — **mitigation:** обязательный чекбокс, ссылки доступны.
- R1.2.4-2: Юридическая сила соглашения — **mitigation:** фиксация IP, даты, версии документа.

---

#### US-1.2.5. Завершение регистрации и создание аккаунта родителя

**Приоритет: P0**

**Как** новый пользователь,
**я хочу** завершить регистрацию и получить доступ к личному кабинету,
**чтобы** начать пользоваться сервисом.

**Критерии приёмки:
1. После подтверждения email и принятия соглашения создаётся аккаунт родителя.
2. Пользователь перенаправляется на главный экран (дашборд или экран приветствия).
3. Аккаунт содержит базовые данные: email, статус подтверждения, дата создания.
4. Пользователь может сразу использовать доступные функции (например, чат-помощник).

**Риски:**
- R1.2.5-1: Аккаунт может быть создан мошенником — **mitigation:** подтверждение email, модерация.
- R1.2.5-2: Данные аккаунта могут быть утеряны — **mitigation:** резервное копирование.

### Эпик 1.3 Восстановление доступа

**Описание:** эпик описывает процесс восстановления доступа к аккаунту родителя при потере пароля.

**Предусловия:** у пользователя есть подтверждённый аккаунт, но он забыл пароль.

---

#### US-1.3.1. Запрос восстановления пароля по email

**Приоритет: P1**

**Как** пользователь с аккаунтом,
**я хочу** запросить восстановление пароля по email,
**чтобы** получить возможность войти в систему.

**Критерии приёмки:
1. На экране входа есть кнопка/ссылка «Забыли пароль?».
2. Пользователь вводит email, указанный при регистрации.
3. При вводе несуществующего email система не сообщает об этом напрямую (из соображений безопасности).
4. Запрос на восстановление отправляется в течение нескольких секунд.

**Риски:**
- R1.3.1-1: Email может быть несуществующим — **mitigation:** не раскрывать факт существования email.
- R1.3.1-2: Массовые запросы восстановления — **mitigation:** rate limiting, капча.

---

#### US-1.3.2. Получение ссылки/кода восстановления

**Приоритет: P1**

**Как** пользователь с аккаунтом,
**я хочу** получить ссылку или код на email для восстановления пароля,
**чтобы** подтвердить свою личность.

**Критерии приёмки:
1. На указанный email отправляется письмо со ссылкой для восстановления.
2. Альтернативно — письмо может содержать одноразовый код для ввода вручную.
3. Ссылка имеет ограниченный срок действия (например, 1 час).
4. Письмо не содержит конфиденциальной информации (старого пароля).

**Риски:**
- R1.3.2-1: Письмо может попасть в спам — **mitigation:** whitelist домена, инструкция для пользователя.
- R1.3.2-2: Ссылка может быть перехвачена — **mitigation:** одноразовый токен, короткий срок.

---

#### US-1.3.3. Установка нового пароля

**Приоритет: P1**

**Как** пользователь с аккаунтом,
**я хочу** установить новый пароль через ссылку из письма,
**чтобы** восстановить доступ к аккаунту.

**Критерии приёмки:
1. По переходу по ссылке открывается форма ввода нового пароля.
2. Требования к новому паролю аналогичны требованиям при регистрации.
3. После успешной смены пароля пользователь перенаправляется на экран входа.
4. Старый пароль аннулируется — все активные сессии с ним завершаются.

**Риски:**
- R1.3.3-1: Пользователь может потерять доступ — **mitigation:** подтверждение через email.
- R1.3.3-2: Сессии могут не завершиться — **mitigation:** инвалидация токенов на сервере.

---

### Эпик 1.4 Подключение ребёнка к аккаунту

**Описание:** эпик описывает процесс подключения профиля ребёнка к аккаунту родителя по коду или ссылке без необходимости собственной электронной почты.

**Предусловия:** родитель имеет подтверждённый аккаунт.

---

#### US-1.4.1. Генерация кода/ссылки для подключения ребёнка

**Приоритет: P0**

**Как** родитель,
**я хочу** сгенерировать уникальный код или ссылку для подключения ребёнка,
**чтобы** пригласить ребёнка в систему.

**Критерии приёмки:
1. Родитель нажимает кнопку «Добавить ребёнка» в настройках аккаунта.
2. Система генерирует уникальный одноразовый код или ссылку с ограниченным сроком действия.
3. Код/ссылка отображается на экране и может быть скопирована или отправлена ребёнку.
4. Родитель может отозвать сгенерированную ссылку до использования.

**Риски:**
- R1.4.1-1: Ссылка может быть перехвачена третьим лицом — **mitigation:** одноразовая, короткий срок действия.
- R1.4.1-2: Родитель может потерять ссылку — **mitigation:** повторная генерация.

---

#### US-1.4.2. Подключение ребёнка по коду/ссылке без собственного email

**Приоритет: P0**

**Как** ребёнок (или родитель),
**я хочу** подключиться к аккаунту родителя по коду или ссылке,
**чтобы** создать профиль ребёнка без необходимости в собственной электронной почте.

**Критерии приёмки:
1. Ребёнок вводит код или переходит по ссылке, полученной от родителя.
2. Система проверяет корректность и срок действия кода/ссылки.
3. После успешного подключения создаётся профиль ребёнка, привязанный к аккаунту родителя.
4. Ребёнок не получает и не использует собственную электронную почту.

**Риски:**
- R1.4.2-1: Код/ссылка может быть использован посторонним — **mitigation:** одноразовый, привязка к аккаунту родителя.
- R1.4.2-2: Ребёнок может потерять доступ — **mitigation:** родитель может перегенерировать код.

---

#### US-1.4.3. Вход ребёнка в детский интерфейс

**Приоритет: P0**

**Как** подключённый ребёнок,
**я хочу** войти в адаптированный детский интерфейс,
**чтобы** пользоваться играми и ИИ-помощником.

**Критерии приёмки:
1. После подключения ребёнок попадает в детский интерфейс с упрощённым дизайном.
2. Интерфейс содержит доступные элементы: игры, ИИ-помощник, друзья (если реализовано).
3. Доступные действия ребёнка ограничены в соответствии с политикой безопасности.
4. Ребёнок не имеет доступа к настройкам аккаунта или данным родителя.

**Риски:**
- R1.4.3-1: Ребёнок может получить доступ к данным родителя — **mitigation:** разделение интерфейсов, ролевой доступ.
- R1.4.3-2: Детский интерфейс может быть запутанным — **mitigation:** тестирование на детской аудитории.

---

#### US-1.4.4. Отключение/переподключение профиля ребёнка

**Приоритет: P2**

**Как** родитель,
**я хочу** отключить или переподключить профиль ребёнка к своему аккаунту,
**чтобы** управлять доступом ребёнка к сервису.

**Критерии приёмки:
1. Родитель может отключить профиль ребёнка из раздела настроек.
2. При отключении профиль ребёнка сохраняется (не удаляется), но теряет доступ к сервису.
3. Родитель может переподключить профиль по ранее сгенерированной ссылке/коду.
4. История данных ребёнка сохраняется при отключении и восстанавливается при переподключении.

**Риски:**
- R1.4.4-1: Данные могут быть утеряны при отключении — **mitigation:** резервное копирование.
- R1.4.4-2: Профиль может быть переподключён посторонним — **mitigation:** одноразовая ссылка.

### Эпик 1.5 Управление сессией и выход

**Описание:** эпик описывает управление активной сессией пользователя, включая сохранение сессии, выход и переключение между интерфейсами.

**Предусловия:** пользователь авторизован в системе.

---

#### US-1.5.1. Сохранение сессии пользователя

**Приоритет: P1**

**Как** авторизованный пользователь,
**я хочу**, чтобы моя сессия сохранялась при повторном посещении,
**чтобы** не вводить данные входа каждый раз.

**Критерии приёмки:
1. Сессия сохраняется в соответствии с политикой хранения сессий (cookie/local storage).
2. Срок действия сессии настраивается пользователем (например, «Запомнить меня»).
3. При истечении срока сессии пользователь перенаправляется на экран входа.
4. Сессия автоматически завершается при выходе или смене устройства.

**Риски:**
- R1.5.1-1: Сессия может быть украдена — **mitigation:** secure cookies, HTTPS.
- R1.5.1-2: Пользователь может потерять данные при смене устройства — **mitigation:** облачная синхронизация.

---

#### US-1.5.2. Выход из аккаунта

**Приоритет: P1**

**Как** авторизованный пользователь,
**я хочу** выйти из аккаунта,
**чтобы** обеспечить безопасность при использовании общего устройства.

**Критерии приёмки:
1. Кнопка «Выйти» доступна в меню пользователя.
2. При нажатии сессия пользователя аннулируется.
3. Пользователь перенаправляется на экран входа или главную страницу.
4. При выходе данные сессии очищаются с устройства (если выбран соответствующий режим).

**Риски:**
- R1.5.2-1: Пользователь может забыть выйти на общем устройстве — **mitigation:** авто-выход, режим общего устройства.
- R1.5.2-2: Сессия может быть не аннулирована — **mitigation:** серверная инвалидация.

---

#### US-1.5.3. Переключение между интерфейсом родителя и ребёнка

**Приоритет: P1**

**Как** родитель с подключёнными профилями детей,
**я хочу** переключаться между родительским и детским интерфейсом,
**чтобы** управлять доступом и проверять активность ребёнка.

**Критерии приёмки:
1. Кнопка переключения интерфейса доступна в меню авторизованного родителя.
2. При переключении в детский интерфейс загружается адаптированный интерфейс для ребёнка.
3. При переключении в родительский интерфейс загружается дашборд с данными о детях.
4. Состояние сессии сохраняется при переключении между интерфейсами.

**Риски:**
- R1.5.3-1: Ребёнок может случайно получить доступ к родительским данным — **mitigation:** чёткое разделение интерфейсов, проверка прав.
- R1.5.3-2: Состояние может не сохраниться — **mitigation:** тестирование переключения.

## Раздел 2. Профили ребёнка

**Описание:** раздел охватывает создание, настройку и управление профилями детей, привязанных к аккаунту родителя.

**Роли:**
- **Родитель** — создаёт и управляет профилями детей.
- **Ребёнок** — использует свой профиль в рамках ограниченного детского интерфейса.

---

### Эпик 2.1 Создание профиля ребёнка

**Описание:** эпик описывает процесс создания профиля ребёнка с указанием базовых данных и выбором аватара.

**Предусловия:** родитель авторизован и имеет активную сессию подключения ребёнка.

---

#### US-2.1.1. Ввод имени/никнейма ребёнка

**Приоритет: P0**

**Как** родитель,
**я хочу** ввести имя или никнейм для профиля ребёнка,
**чтобы** ребёнок мог идентифицировать себя в системе.

**Критерии приёмки:
1. На экране создания профиля отображается поле для ввода имени/никнейма.
2. Имя/никнейм может содержать только допустимые символы (буквы, цифры, пробелы).
3. Длина имени ограничена (например, от 2 до 20 символов).
4. Система проверяет уникальность имени/никнейма среди других пользователей.

**Риски:**
- R2.1.1-1: Имя может быть некорректным — **mitigation:** валидация символов, модерация.
- R2.1.1-2: Имя может быть использовано для идентификации ребёнка — **mitigation:** никнейм вместо реального имени.

---

#### US-2.1.2. Указание возраста ребёнка

**Приоритет: P0**

**Как** родитель,
**я хочу** указать возраст ребёнка при создании профиля,
**чтобы** система могла адаптировать контент и рекомендации.

**Критерии приёмки:
1. На экране создания профиля отображается поле выбора возраста (например, выпадающий список или слайдер).
2. Возраст ограничивается допустимым диапазоном для целевой аудитории (например, 5–16 лет).
3. Указанный возраст используется для фильтрации игр и рекомендаций.
4. Родитель может изменить возраст ребёнка в настройках профиля.

**Риски:**
- R2.1.2-1: Неверный возраст — **mitigation:** родитель указывает данные, система не проверяет.
- R2.1.2-2: Неподходящий контент из-за неверного возраста — **mitigation:** рекомендации родителю.

---

#### US-2.1.3. Выбор аватара ребёнка

**Приоритет: P1**

**Как** родитель (или ребёнок),
**я хочу** выбрать аватар для профиля ребёнка из каталога,
**чтобы** персонализировать профиль и отличать его от других.

**Критерии приёмки:
1. При создании профиля отображается каталог доступных аватаров для выбора.
2. Каталог содержит набор тематических аватаров, адаптированных для детской аудитории.
3. Выбранный аватар отображается в профиле ребёнка, в списке друзей и в чатах.
4. Родитель (или ребёнок при разрешении) может сменить аватар в настройках профиля.

**Риски:**
- R2.1.3-1: Аватар может быть неуместным — **mitigation:** каталог предустановленных аватаров без загрузки.
- R2.1.3-2: Ребёнок может сменить аватар без ведома родителя — **mitigation:** настройки родительского контроля.

---

#### US-2.1.4. Сохранение профиля ребёнка

**Приоритет: P0**

**Как** родитель,
**я хочу** сохранить созданный профиль ребёнка,
**чтобы** ребёнок мог начать пользоваться сервисом.

**Критерии приёмки:
1. После заполнения всех обязательных полей профиль сохраняется в системе.
2. Профиль привязывается к аккаунту родителя и становится доступным в списке детей.
3. После сохранения ребёнок может войти в детский интерфейс.
4. Данные профиля сохраняются в соответствии с политикой хранения чувствительных данных.

**Риски:**
- R2.1.4-1: Данные могут быть утеряны — **mitigation:** резервное копирование.
- R2.1.4-2: Несанкционированный доступ — **mitigation:** шифрование, авторизация.

---

### Эпик 2.2 Управление профилями детей

**Описание:** эпик описывает управление существующими профилями детей: просмотр, редактирование, удаление и добавление нескольких детей.

**Предусловия:** родитель имеет один или несколько подключённых профилей детей.

---

#### US-2.2.1. Просмотр списка профилей детей

**Приоритет: P1**

**Как** родитель,
**я хочу** просмотреть список всех подключённых профилей детей,
**чтобы** управлять их активностью и данными.

**Критерии приёмки:
1. На экране настроек аккаунта отображается список всех профилей детей.
2. Для каждого профиля отображается имя, аватар и возраст.
3. Родитель может выбрать профиль для просмотра деталей или управления.
4. Если профилей нет, отображается подсказка с предложением добавить ребёнка.

**Риски:**
- R2.2.1-1: Данные могут быть несвоевременно обновлены — **mitigation:** кэширование с инвалидацией.
- R2.2.1-2: Родитель может не увидеть профиль — **mitigation:** уведомления.

---

#### US-2.2.2. Редактирование профиля ребёнка

**Приоритет: P1**

**Как** родитель,
**я хочу** редактировать данные профиля ребёнка (имя, возраст, аватар),
**чтобы** актуализировать информацию.

**Критерии приёмки:
1. Родитель может изменить имя/никнейм, возраст и аватар профиля.
2. При изменении имени система проверяет уникальность нового имени.
3. Изменения сохраняются мгновенно и применяются во всех разделах сервиса.
4. История изменений профиля не ведётся (данные перезаписываются).

**Риски:**
- R2.2.2-1: Родитель может ввести некорректные данные — **mitigation:** валидация.
- R2.2.2-2: Изменения могут не примениться — **mitigation:** транзакции, логирование.

---

#### US-2.2.3. Удаление профиля ребёнка

**Приоритет: P1**

**Как** родитель,
**я хочу** удалить профиль ребёнка,
**чтобы** управлять списком подключённых детей или прекратить хранение данных.

**Критерии приёмки:
1. Родитель может инициировать удаление профиля из раздела настроек.
2. Перед удалением отображается предупреждение о безвозвратном удалении данных.
3. При удалении профиля удаляются все связанные данные: прогресс игр, эмоциональные маркеры и т.д.
4. Удаление невозможно, если это единственный профиль ребёнка (или система предлагает перенести данные).

**Риски:**
- R2.2.3-1: Данные могут быть удалены по ошибке — **mitigation:** подтверждение удаления, корзина.
- R2.2.3-2: Удаление может повлиять на дочерние данные — **mitigation:** каскадное удаление с предупреждением.

---

#### US-2.2.4. Добавление нескольких детей к одному аккаунту

**Приоритет: P2**

**Как** родитель,
**я хочу** добавить несколько профилей детей к одному аккаунту,
**чтобы** вести учёт активности для каждого ребёнка отдельно.

**Критерии приёмки:
1. Родитель может добавить неограниченное (или ограниченное системой, например, до 5) количество профилей детей.
2. Каждый профиль ребёнка создаётся по отдельности через код/ссылку подключения.
3. Родитель может переключаться между профилями детей для просмотра данных.
4. Дашборд и отчёты отображаются по каждому ребёнку отдельно.

**Риски:**
- R2.2.4-1: Родитель может превысить лимит детей — **mitigation:** ограничение на уровне системы.
- R2.2.4-2: Данные могут перемешаться — **mitigation:** чёткая привязка к аккаунту.

---

### Эпик 2.3 Использование продукта без профилей детей

**Описание:** эпик описывает сценарии использования продукта родителем без обязательного добавления профилей детей — в первую очередь через чат-помощник.

**Предусловия:** родитель имеет подтверждённый аккаунт.

---

#### US-2.3.1. Доступ родителя к продукту без добавленных детей

**Приоритет: P1**

**Как** родитель без подключённых детей,
**я хочу** пользоваться основными функциями сервиса,
**чтобы** получать пользу от платформы независимо от наличия детей в профиле.

**Критерии приёмки:
1. Родитель может войти в аккаунт и получить доступ к основному интерфейсу без профилей детей.
2. Доступны функции, не требующие привязки к ребёнку (например, чат-помощник).
3. Функции, требующие профиля ребёнка (дашборд, игры), недоступны или заблокированы.
4. На главном экране отображается предложение добавить ребёнка (необязательный шаг).

**Риски:**
- R2.3.1-1: Родитель может не получить доступ к дашборду — **mitigation:** чёткая навигация.
- R2.3.1-2: Функции могут быть недоступны — **mitigation:** понятные сообщения.

---

#### US-2.3.2. Доступ к чат-помощнику без профилей детей

**Приоритет: P1**

**Как** родитель без подключённых детей,
**я хочу** общаться с чат-помощником для получения советов по воспитанию,
**чтобы** решать вопросы воспитания в рамках заданной методологии.

**Критерии приёмки:
1. Чат-помощник доступен на главном экране родителю без профилей детей.
2. Родитель может задавать вопросы о воспитании, получать ответы в рамках методологии.
3. История диалогов сохраняется и доступна в соответствующем разделе.
4. Ответы помощника проходят модерацию и содержат предупреждение о консультации специалиста при рисковых темах.

**Риски:**
- R2.3.2-1: Ответы могут быть некорректными — **mitigation:** модерация, RAG.
- R2.3.2-2: Родитель может получить вредный совет — **mitigation:** экспертная проверка.

---

#### US-2.3.3. Предложение добавить ребёнка (необязательный шаг)

**Приоритет: P3**

**Как** родитель без подключённых детей,
**я хочу** получить предложение добавить ребёнка в систему,
**чтобы** раскрыть полный функционал платформы.

**Критерии приёмки:
1. При входе в систему родитель видит ненавязчивое предложение добавить профиль ребёнка.
2. Предложение можно отложить или отклонить без блокировки основных функций.
3. После добавления ребёнка родитель получает доступ к дашборду, играм и детскому ИИ-помощнику.
4. Отклонение предложения не влияет на доступ к чат-помощнику для родителей.

**Риски:**
- R2.3.3-1: Предложение может быть навязчивым — **mitigation:** ненавязчивый дизайн, возможность отложить.
- R2.3.3-2: Родитель может не заметить предложение — **mitigation:** повторное отображение.

## Раздел 3. Развивающие игры для детей

**Описание:** раздел охватывает каталог развивающих игр на софт-навыки, процесс прохождения игр ребёнком и фиксацию прогресса.

**Роли:**
- **Ребёнок** — играет в игры, видит свой прогресс.
- **Родитель** — просматривает прогресс ребёнка в играх.

---

### Эпик 3.1 Каталог игр

**Описание:** эпик описывает просмотр каталога развивающих игр, фильтрацию по навыкам и рекомендации по возрасту.

**Предусловия:** ребёнок авторизован в детском интерфейсе.

---

#### US-3.1.1. Просмотр каталога игр на софт-навыки

**Приоритет: P1**

**Как** ребёнок,
**я хочу** просматривать каталог развивающих игр,
**чтобы** выбрать интересную игру для развития навыков.

**Критерии приёмки:
1. Каталог отображается на главном экране детского интерфейса.
2. Каждая игра представлена карточкой с названием, иконкой и кратким описанием.
3. Каталог содержит игры, направленные на развитие эмоционального интеллекта, коммуникации и саморегуляции.
4. Каталог адаптирован для детской аудитории с ярким, дружелюбным дизайном.

**Риски:**
- R3.1.1-1: Каталог может быть пустым — **mitigation:** заглушки, сообщения.
- R3.1.1-2: Дизайн может быть неадаптивным — **mitigation:** тестирование на устройствах.

---

#### US-3.1.2. Фильтрация игр по навыку (эмоциональный интеллект, коммуникация, саморегуляция)

**Приоритет: P2**

**Как** ребёнок (или родитель),
**я хочу** фильтровать игры по типу развиваемого навыка,
**чтобы** выбирать игры, направленные на конкретную область развития.

**Критерии приёмки:
1. На экране каталога отображаются фильтры по навыкам (эмоциональный интеллект, коммуникация, саморегуляция).

3. Возможность выбрать несколько фильтров для комбинированной фильтрации.
4. Если фильтры не выбраны, отображаются все доступные игры.

**Риски:**
- R3.1.2-1: Фильтры могут работать некорректно — **mitigation:** тестирование.
- R3.1.2-2: Неправильная категоризация игр — **mitigation:** экспертная проверка.

**Риски:**

#### US-3.1.4. Рекомендации игр по возрасту ребёнка

### Эпик 3.3 Фиксация прогресса

**Как** система,

**Риски:**
- R3.3.1-1: Прогресс может не сохраниться — **mitigation:** автосохранение, retry.

**Риски:**

**Как** ребёнок,

3. Прогресс обновляется в реальном времени после завершения игры.
4. Интерфейс прогресса адаптирован для детской аудитории.

**Риски:**
- R3.3.3-1: Прогресс может быть непонятен ребёнку — **mitigation:** визуализация.

## Раздел 4. ИИ-помощник для ребёнка

**Описание:** раздел охватывает общение ребёнка с ИИ-помощником, безопасность и модерацию детского чата, а также хранение и удаление переписки.

**Роли:**

- **Система** — обеспечивает модерацию и безопасность.

### Эпик 4.1 Общение с помощником

**Описание:** эпик описывает процесс общения ребёнка с ИИ-помощником для поддержки в моменты грусти и стресса.

**Предусловия:** ребёнок авторизован в детском интерфейсе.

---

#### US-4.1.1. Запуск диалога с ИИ-помощником

**Приоритет: P0**

**Как** ребёнок,
**я хочу** запустить диалог с ИИ-помощником,
**чтобы** получить поддержку в трудной ситуации.

**Критерии приёмки:
1. ИИ-помощник доступен на главном экране детского интерфейса.
2. По нажатию открывается экран чата с помощником.
3. Помощник приветствует ребёнка дружелюбным сообщением.
4. Помощник ожидает ввод сообщения от ребёнка.

**Риски:**
- R4.1.1-1: Помощник может не загрузиться — **mitigation:** fallback.
- R4.1.1-2: Ребёнок может не найти помощника — **mitigation:** заметная иконка.

---

#### US-4.1.2. Поддержка ребёнка в моменты грусти и стресса

**Приоритет: P0**

**Как** ребёнок,
**я хочу** получать поддержку от ИИ-помощника в моменты грусти и стресса,
**чтобы** почувствовать себя лучше.

**Критерии приёмки:
1. Помощник отвечает на сообщения ребёнка доброжелательным тоном.
2. Помощник задаёт уточняющие вопросы для понимания ситуации.
3. Помощник предлагает простые техники самопомощи (дыхательные упражнения, отвлечение).
4. Ответы адаптированы для детской аудитории (простой язык, эмпатия).

**Риски:**
- R4.1.2-1: Ответы могут быть неэмпатичными — **mitigation:** тестирование, экспертная проверка.
- R4.1.2-2: Ребёнок может не получить помощь — **mitigation:** escalation к специалисту.

---

#### US-4.1.3. Ведение диалога по ограниченному безопасному сценарию

**Приоритет: P0**

**Как** ребёнок,
**я хочу** общаться с ИИ-помощником в рамках безопасного сценария,
**чтобы** быть уверенным в безопасности общения.

**Критерии приёмки:
1. Помощник ограничивает темы разговора безопасными для детской аудитории.
2. Помощник не обсуждает темы, не относящиеся к эмоциональному благополучию и воспитанию.
3. Помощник перенаправляет разговор, если ребёнок задаёт неподходящий вопрос.
4. Все ответы генерируются в рамках заданных ограничений.

**Риски:**
- R4.1.3-1: Помощник может выйти за рамки — **mitigation:** строгие ограничения.
- R4.1.3-2: Ребёнок может быть расстроен — **mitigation:** эмпатичный дизайн.

### Эпик 4.2 Безопасность и модерация детского чата

**Описание:** эпик описывает механизмы безопасности, модерации и перенаправления к специалисту при рисковых темах.

**Предусловия:** ребёнок начал диалог с ИИ-помощником.

---

#### US-4.2.1. Модерация сообщений детского чата

**Приоритет: P0**

**Как** система,
**я хочу** модерировать все сообщения детского чата,
**чтобы** обеспечить безопасность общения ребёнка.

**Критерии приёмки:
1. Каждое сообщение ребёнка проходит автоматическую модерацию перед отправкой помощнику.
2. Каждое сообщение помощника проходит модерацию перед отображением ребёнку.
3. Модерация проверяет контент на соответствие детской аудитории.
4. Небезопасные сообщения блокируются и не отображаются.

**Риски:**
- R4.2.1-1: Ложные срабатывания — **mitigation:** тонкая настройка.
- R4.2.1-2: Пропуск опасных сообщений — **mitigation:** многослойная модерация.

---

#### US-4.2.2. Распознавание рискованных тем

**Приоритет: P0**

**Как** система,
**я хочу** распознавать риски в сообщениях ребёнка,
**чтобы** принять меры при угрозе безопасности ребёнка.

**Критерии приёмки:
1. Система автоматически анализирует сообщения ребёнка на наличие признаков риска (насилие, буллинг, суицидальные мысли).
2. При распознавании риска система фиксирует событие для дальнейшей обработки.
3. Риск-сигналы не передаются третьим лицам без согласия родителя (если не требуется по закону).
4. Система обновляет модели распознавания на основе обратной связи.

**Риски:**
- R4.2.2-1: Ложные срабатывания — **mitigation:** валидация.
- R4.2.2-2: Пропуск реальных рисков — **mitigation:** регулярное обновление.

---

#### US-4.2.3. Мягкое перенаправление к специалисту при рисковых темах

**Приоритет: P0**

**Как** ребёнок,
**я хочу** получить мягкое перенаправление к специалисту при рисковых темах,
**чтобы** получить помощь, не чувствуя страха или тревоги.

**Критерии приёмки:
1. При распознавании риска помощник мягко предлагает обратиться к взрослому или специалисту.
2. Сообщение помощника не пугает ребёнка и не содержит тревожной терминологии.
3. Помощник предлагает контакты службы доверия или рекомендует поговорить с родителем.
4. Риск-сигнал фиксируется и может быть отображён родителю в дашборде (с согласия родителя).

**Риски:**
- R4.2.3-1: Ребёнок может испугаться — **mitigation:** мягкий тон.
- R4.2.3-2: Родитель может не увидеть сигнал — **mitigation:** уведомления.

---

#### US-4.2.4. Ограничение сценариев общения помощника

**Приоритет: P0**

**Как** система,
**я хочу** ограничивать сценарии общения ИИ-помощника,
**чтобы** исключить нежелательные темы и поведение.

**Критерии приёмки:
1. Помощник имеет заданный набор сценариев общения, утверждённых экспертами.
2. Помощник не инициирует разговоры и не задаёт вопросы без запроса ребёнка.
3. Помощник не собирает персональные данные ребёнка (имя, адрес, школа и т.д.).
4. Сценарии общения могут быть обновлены родителем или администратором платформы.

**Риски:**
- R4.2.4-1: Помощник может выйти за рамки — **mitigation:** валидация сценариев.
- R4.2.4-2: Утечка данных — **mitigation:** шифрование.

#### US-4.3.2. Удаление переписки ребёнка

**Приоритет: P1**

**Как** родитель,

2. Переписка не используется для обучения моделей без явного согласия родителя.
3. Данные ребёнка не передаются третьим лицам.
4. Родитель может просмотреть, какие данные о ребёнке хранятся в системе.

**Риски:**

### Эпик 5.3 Чат между детьми

**Предусловия:** ребёнок и другой ребёнок являются друзьями.

#### US-5.3.1. Переписка с другим ребёнком в чате

**Приоритет: P2**

**Как** ребёнок,

**Риски:**

#### US-5.3.2. Просмотр истории переписки с другим ребёнком

**Приоритет: P2**

**Как** ребёнок,

**Риски:**
- R5.3.2-1: История может быть неполной — **mitigation:** пагинация.

#### US-5.3.3. Модерация сообщений детского чата между детьми

**Приоритет: P0**

**Как** система,

### Эпик 6.2 Качество и модерация ответов

**Описание:** эпик описывает механизмы формирования ответов на базе методологии, модерацию и перенаправление к специалисту при рисковых темах.

---

#### US-6.2.1. Формирование ответов на базе методологии (RAG/файн-тюнинг)

**Приоритет: P0**

**Как** система,
**я хочу** формировать ответы чат-помощника на основе загруженной методологии,
**чтобы** обеспечить качество и релевантность рекомендаций.

**Критерии приёмки:
1. Помощник использует RAG (Retrieval-Augmented Generation) или файн-тюненую модель для генерации ответов.
2. База знаний помощника включает методологию позитивного родительства.
3. Ответы ссылаются на источники из методологии.
4. Помощник может указать, что ответ основан на общих принципах, если точный источник не найден.

**Риски:**
- R6.2.1-1: Ответы могут быть нерелевантными — **mitigation:** RAG.
- R6.2.1-2: Устаревшая база — **mitigation:** обновление.

---

#### US-6.2.2. Модерация ответов помощника

**Приоритет: P0**

**Как** система,
**я хочу** модерировать ответы чат-помощника,
**чтобы** исключить некорректные или вредные рекомендации.

**Критерии приёмки:
1. Каждый ответ помощника проходит автоматическую модерацию перед отображением родителю.
2. Модерация проверяет ответы на соответствие методологии и отсутствие вредных рекомендаций.
3. Небезопасные ответы блокируются и заменяются на нейтральный текст.
4. Факт блокировки ответа фиксируется в журнале модерации.

**Риски:**
- R6.2.2-1: Вредные рекомендации — **mitigation:** модерация.
- R6.2.2-2: Пропуск — **mitigation:** многослойная.

---

#### US-6.2.3. Перенаправление к специалисту при темах, связанных с риском

**Приоритет: P1**

**Как** родитель,
**я хочу** получить перенаправление к специалисту при темах, связанных с риском,
**чтобы** получить профессиональную помощь в сложной ситуации.

**Критерии приёмки:
1. При распознавании рисковой темы помощник мягко рекомендует обратиться к специалисту.
2. Помощник не даёт медицинских или психиатрических диагнозов.
3. Помощник предлагает контакты специалистов или служб поддержки.
4. Рекомендация специалиста не заменяет профессиональную консультацию.

**Риски:**
- R6.2.3-1: Родитель может не получить помощь — **mitigation:** контакты.
- R6.2.3-2: Неправильное перенаправление — **mitigation:** валидация.

## Раздел 7. Дашборд родителя

**Описание:** раздел охватывает обзор по ребёнку, отображение активности в играх, динамики развития навыков и эмоционального состояния.

**Роли:**
- **Родитель** — просматривает дашборд по каждому ребёнку.

---

### Эпик 7.1 Обзор по ребёнку

**Описание:** эпик описывает выбор ребёнка для просмотра дашборда и просмотр сводной информации о занятиях и успехах.

**Предусловия:** родитель имеет один или несколько подключённых профилей детей.

---

#### US-7.1.1. Выбор ребёнка для просмотра дашборда

**Приоритет: P1**

**Как** родитель,
**я хочу** выбрать ребёнка для просмотра дашборда,
**чтобы** увидеть информацию о конкретном ребёнке.

**Критерии приёмки:
1. На главном экране дашборда отображается список подключённых детей.
2. Родитель может переключаться между профилями детей.
3. Для каждого ребёнка отображается аватар и имя для быстрой идентификации.
4. Данные дашборда обновляются при переключении между детьми.

**Риски:**
- R7.1.1-1: Данные могут не обновиться — **mitigation:** real-time.
- R7.1.1-2: Путаница между детьми — **mitigation:** чёткое разделение.

---

#### US-7.1.2. Просмотр сводной информации о занятиях и успехах

**Приоритет: P1**

**Как** родитель,
**я хочу** просмотреть сводную информацию о занятиях и успехах ребёнка,
**чтобы** иметь общее представление о прогрессе.

**Критерии приёмки:
1. На экране дашборда отображается сводка: количество игр, пройденных за период, полученные достижения.
2. Сводка включает данные за выбранный период (неделя, месяц, всё время).
3. Данные представлены в виде карточек или виджетов.
4. Сводка обновляется в реальном времени при новых действиях ребёнка.

**Риски:**
- R7.1.2-1: Данные могут быть неточными — **mitigation:** валидация.
- R7.1.2-2: Родитель может не понять — **mitigation:** визуализация.

---

### Эпик 7.2 Активность в играх

**Описание:** эпик описывает просмотр активности ребёнка в играх и динамики развития навыков.

**Предусловия:** ребёнок прошёл хотя бы одну игру.

---

#### US-7.2.1. Просмотр активности ребёнка в играх

**Приоритет: P1**

**Как** родитель,
**я хочу** просматривать активность ребёнка в играх,
**чтобы** видеть, сколько и каких игр он прошёл.

**Критерии приёмки:
1. На дашборде отображается список игр, пройденных ребёнком.
2. Для каждой игры отображается название, дата прохождения и результат.
3. Активность отображается за выбранный период (неделя, месяц, всё время).
4. Родитель может перейти к детальной информации по каждой игре.

**Риски:**
- R7.2.1-1: Данные могут быть неполными — **mitigation:** бэкап.
- R7.2.1-2: Родитель может не понять — **mitigation:** пояснения.

---

#### US-7.2.2. Просмотр динамики развития навыков

**Приоритет: P1**

**Как** родитель,
**я хочу** просматривать динамику развития навыков ребёнка,
**чтобы** отслеживать прогресс в эмоциональном интеллекте, коммуникации и саморегуляции.

**Критерии приёмки:
1. На дашборде отображаются графики или диаграммы по каждому навыку.
2. Графики показывают динамику изменения уровня навыка за период.
3. Данные основаны на результатах пройденных игр.
4. Родитель может выбрать период для отображения динамики.

**Риски:**
- R7.2.2-1: Данные могут быть неточными — **mitigation:** валидация.
- R7.2.2-2: Неправильная интерпретация — **mitigation:** пояснения.

---

### Эпик 7.3 Эмоциональное состояние

**Описание:** эпик описывает просмотр эмоциональных маркеров ребёнка и динамики его эмоционального состояния.

**Предусловия:** ребёнок общался с ИИ-помощником или проходил игры, фиксирующие эмоциональные маркеры.

---

#### US-7.3.1. Просмотр эмоциональных маркеров ребёнка

**Приоритет: P1**

**Как** родитель,
**я хочу** просматривать эмоциональные маркеры ребёнка,
**чтобы** понимать его текущее эмоциональное состояние.

**Критерии приёмки:
1. На дашборде отображается текущий эмоциональный маркер ребёнка (например, смайл с описанием).
2. Эмоциональные маркеры формируются на основе общения с ИИ-помощником и результатов игр.
3. Маркеры не содержат подробной переписки или конфиденциальной информации.
4. Родитель может увидеть дату и время последнего обновления маркера.

**Риски:**
- R7.3.1-1: Маркеры могут быть неточными — **mitigation:** валидация.
- R7.3.1-2: Родитель может неправильно интерпретировать — **mitigation:** пояснения.

---

#### US-7.3.2. Отображение динамики эмоционального состояния

**Приоритет: P2**

**Как** родитель,
**я хочу** просматривать динамику эмоционального состояния ребёнка,
**чтобы** отслеживать изменения и выявлять закономерности.

**Критерии приёмки:
1. На дашборде отображается график эмоциональных маркеров за период.
2. График показывает изменения эмоционального состояния во времени.
3. Родитель может выбрать период для отображения динамики.
4. При обнаружении негативной тенденции система может предложить обратить внимание или обратиться к специалисту.

**Риски:**
- R7.3.2-1: Ложные срабатывания — **mitigation:** настройка.
- R7.3.2-2: Родитель может не увидеть — **mitigation:** уведомления.

## Раздел 8. Приватность и управление данными

**Описание:** раздел охватывает политику хранения и удаления данных, управление согласиями и удаление аккаунта.

**Роли:**

### Эпик 8.1 Политика хранения и удаления данных

**Описание:** эпик описывает настройку политики хранения переписки, удаление данных ребёнка и минимизацию собираемых данных.

**Предусловия:** родитель имеет аккаунт с подключёнными профилями детей.

---

#### US-8.1.1. Настройка политики хранения переписки

**Приоритет: P1**

**Как** родитель,
**я хочу** настраивать политику хранения переписки ребёнка,
**чтобы** контролировать, как долго данные хранятся в системе.

**Критерии приёмки:
1. В разделе настроек приватности родитель может выбрать период хранения переписки.
2. Доступные варианты: 7 дней, 30 дней, 90 дней, не удалять.
3. Изменения применяются ко всей переписке ребёнка (ИИ-помощник, чат с детьми).
4. При сокращении периода старые сообщения удаляются автоматически.

**Риски:**
- R8.1.1-1: Данные могут быть удалены по ошибке — **mitigation:** подтверждение.
- R8.1.1-2: Родитель может не понять — **mitigation:** пояснения.

---

#### US-8.1.2. Удаление данных ребёнка по запросу родителя

**Приоритет: P1**

**Как** родитель,
**я хочу** удалить все данные ребёнка из системы,
**чтобы** прекратить хранение чувствительной информации.

**Критерии приёмки:
1. Родитель может инициировать удаление всех данных ребёнка из раздела настроек.
2. Перед удалением отображается подробный список удаляемых данных.
3. Удаление происходит мгновенно и безвозвратно.
4. После удаления аккаунт и все профили ребёнка удаляются из системы.

**Риски:**
- R8.1.2-1: Данные могут быть удалены по ошибке — **mitigation:** подтверждение.
- R8.1.2-2: Восстановление невозможно — **mitigation:** предупреждение.

---

#### US-8.1.3. Минимизация собираемых данных

**Приоритет: P1**

**Как** система,
**я хочу** минимизировать собираемые данные,
**чтобы** соблюдать принцип минимальной достаточности.

**Критерии приёмки:
1. Система собирает только необходимые данные для работы сервиса.
2. Данные ребёнка не используются для целей, не связанных с работой сервиса.
3. Система не собирает геолокацию, контакты родителей и другие избыточные данные.
4. Родитель может просмотреть список собираемых данных в разделе приватности.

**Риски:**
- R8.1.3-1: Сбор избыточных данных — **mitigation:** аудит.
- R8.1.3-2: Утечка — **mitigation:** шифрование.

### Эпик 8.2 Согласия и управление доступом

---

#### US-8.2.2. Просмотр и экспорт собранных данных

**Приоритет: P2**

**Как** родитель,
**я хочу** просмотреть и экспортировать все собранные данные ребёнка,
