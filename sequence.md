# Диаграмма последовательности: создание карточки товара с автозаполнением атрибутов

Основной сценарий первого чекпоинта: селлер М.Видео в личном кабинете поставщика заводит карточку товара; сервис **извлекает значения из текста карточки**, сверяет их со **справочником каталога** (эталон), нормализует и возвращает характеристики с уверенностью.

Важно:
- **Источник сигнала** — название, описание и сырые атрибуты продавца (не «достаём» значение из каталога).
- **Эталон** — справочник каталога: какие атрибуты обязательны для категории и какие значения каноничны.
- **Гибрид по стоимости** — дешёвые методы закрывают типовые случаи; ML и LLM подключаются только к незакрытым атрибутам.

## Участники

| Участник | Роль |
| --- | --- |
| Селлер | Поставщик маркетплейса М.Видео, создаёт карточку |
| ЛК поставщика | UI личного кабинета (экран ввода → ожидание → результат) |
| Сервис извлечения | Пайплайн: препроцессинг → гибридное извлечение → нормализация → мэппинг |
| Справочник атрибутов | Эталон каталога: обязательные поля категории + допустимые значения |
| Каталог М.Видео | Приём проверенных атрибутов в карточку SKU |
| Ручная проверка | Очередь low-confidence / спорных значений (опционально) |

## Sequence diagram

```mermaid
sequenceDiagram
    autonumber
    actor Селлер as Селлер (поставщик М.Видео)
    participant ЛК as ЛК поставщика
    participant API as Сервис извлечения
    participant Справ as Справочник атрибутов<br/>(эталон каталога)
    participant Кат as Каталог М.Видео
    participant Review as Ручная проверка

    Note over Селлер,ЛК: Предусловие: селлер зарегистрирован,<br/>договор подписан (шаг 1 онбординга)

    Селлер->>ЛК: Открывает «Заведите карточки товаров»
    ЛК-->>Селлер: Экран 1: «Введите название и описание товара»

    Селлер->>ЛК: Вводит название, описание<br/>(опционально сырые атрибуты продавца)
    Селлер->>ЛК: Подтверждает отправку

    ЛК-->>Селлер: Экран 2: «Изучаю информацию и готовлю карточку»
    ЛК->>API: POST /extract<br/>{title, description, seller_attrs?}

    Note over API: Источник сигнала = текст карточки

    API->>API: Препроцессинг текста<br/>(очистка HTML, нормализация пробелов)
    API->>Справ: Определить категорию → запросить обязательные поля
    Справ-->>API: Список атрибутов + допустимые значения (эталон)

    Note over API: Гибридный роутер: дешёвое → дорогое<br/>только для незакрытых атрибутов

    API->>API: Слой 1 · Правила и словари<br/>(regex, бренд-лист, цвета, единицы)
    API->>API: Закрытые с высокой уверенностью → готовы

    alt Есть незакрытые атрибуты
        API->>API: Слой 2 · ML / NER<br/>(свободный текст, неочевидные формулировки)
        API->>API: Новые закрытые атрибуты → готовы
    end

    alt Всё ещё есть пробелы / новая категория / cold-start
        API->>API: Слой 3 · LLM (few-shot + JSON-схема)<br/>только по незакрытым полям
        Note over API: LLM дорого на масштабе каталога —<br/>не вызываем для уже найденных полей
    end

    API->>API: Нормализация значений<br/>(«алый»/«red» → «красный», единицы измерения)
    API->>Справ: Мэппинг в канон справочника
    Справ-->>API: Канонические значения / отказ, если нет в эталоне

    API->>API: Уверенность по каждому атрибуту<br/>+ проверка: значение опирается на исходный текст<br/>(анти-галлюцинация)

    alt Уверенность ≥ порога
        API-->>ЛК: {атрибуты: [{name, value, confidence}], title, description}
        ЛК-->>Селлер: Экран 3: карточка с атрибутами,<br/>значениями и уверенностью
        Селлер->>ЛК: Подтверждает / правит значения
        ЛК->>Кат: Сохранить атрибуты в карточку SKU
        Кат-->>ЛК: Карточка обновлена
        ЛК-->>Селлер: Товар готов к шагу «цены и остатки»
    else Уверенность < порога или значение не найдено в тексте
        API-->>ЛК: Атрибуты + флаги low-confidence / пустые поля
        ЛК-->>Селлер: Подсветка сомнительных полей,<br/>запрос ручного ввода
        Селлер->>ЛК: Вводит или подтверждает значение
        ЛК->>Review: Отправить кейс в разметку (feedback loop)
        Review-->>API: Размеченный пример → дообучение / обновление правил
        ЛК->>Кат: Сохранить подтверждённые атрибуты
        Кат-->>ЛК: Карточка обновлена
    end
```

## Гибридная схема (ответ на требование про стоимость)

| Слой | Что делает | Когда включается | Стоимость |
| --- | --- | --- | --- |
| 1. Правила и словари | Явные паттерны в тексте | Всегда первым | Очень низкая |
| 2. ML / NER | Свободные формулировки | Только незакрытые после слоя 1 | Средняя |
| 3. LLM | Cold-start, новые категории, хвост | Только незакрытые после слоя 2 | Высокая |

Итог: типовые карточки закрываются дёшево; LLM не вызывается «на каждую карточку целиком», а точечно — по полям, где без него не обойтись.

## Вход / выход сервиса (для тест-кейсов)

**Запрос (вход) — текст карточки:**
- `title` — название товара
- `description` — свободный текст описания
- `seller_attrs` (опционально) — атрибуты, которые уже указал продавец

**Эталон (не вход селлера, а внутренний справочник):**
- обязательные атрибуты категории
- допустимые / канонические значения

**Ответ (выход):**
- список объектов `{ attribute, value, confidence }`
- только канонические значения из справочника категории
- без выдуманных характеристик: значение должно опираться на текст карточки

**Пример ответа (смартфон):**

| Атрибут | Значение | Уверенность |
| --- | --- | --- |
| Бренд | Samsung | 0,98 |
| Объём памяти | 256 ГБ | 0,95 |
| Диагональ экрана | 6,7 дюйма | 0,93 |
| Цвет | чёрный | 0,81 |

## Связь с онбордингом поставщика

1. Зарегистрируйтесь и подпишите договор  
2. **Заведите карточки товаров** ← здесь встроен наш сервис  
3. Прогрузите цены и остатки
